## 2. How to verify rather than trust

Nothing needs my word. Each claim in the ledger carries its command.

```
python -m pytest tests -q                       # 267 tests, the factual constraints
python -m spinelab.confidence.channels          # the channel table vs the checkpoints
python -m spinelab.gsps.validate <dir>          # dciodvfy over any DICOM directory
python -m spinelab.eval.verse --self-check      # the scorer against known answers
python -m spinelab.outliers.spline --validate   # the synthetic evaluation
python scripts/e1_ablation.py --run-dir <run>   # ablation, ceilings, null
python scripts/make_figures.py                  # every figure, from results/*.json
```

Use the project interpreter. Under a different environment `test_e1_oracles.py`
cannot import `nibabel`, skips as a **single** module-level skip, and the suite
silently reports 249 instead of 267 without erroring. That is worth knowing before
you conclude a number is wrong.

Two design choices exist specifically so you do not have to trust the tool that wrote
the code: **no metric in the paper is computed by code written for the purpose of
computing that metric.** Conformance is scored by `dciodvfy`, an independent
third-party validator. Vertebral identification is scored by the VerSe organisers'
own `eval_utilities.py`, vendored rather than reimplemented. If you distrust one
number above all others, re-run its scorer yourself.

## 3. Where I think this breaks. Attack these first.

### Tier 1, could sink the paper

**3.1 It is a paper about delivering results to viewers, and it measures one viewer
that draws nothing.** Still the strongest objection, but narrower than it was. The
paper now reports the archive and both DICOMweb routes from `results/viewer_bench.md`
in Table 1, so "nothing in the delivery path detected it" rests on measurements
rather than on inference. What remains unmeasured is what a *colour-capable clinical*
viewer draws. Rendering in the target viewer is reported from the deployment's
operating record, and no human scored a viewport. Ask whether the paper concedes that
clearly enough.

**3.2 The entire ablation rests on an out-of-distribution confound.** The model is
MRI-trained; the only public benchmark with named-level ground truth is CT. So the
channel-selection result shows a bug matters *when the model is already far outside
its distribution*. A reviewer can reasonably say: show me this in distribution, or
concede that the effect size is an artefact of a degraded regime. There is no clean
answer available, because no public in-distribution named-level MRI set exists that
is not in the model's training data. This is the paper's deepest structural weakness
and the draft handles it with a limitation sentence, which may not be enough.

**3.2a What does a negative result on one pipeline establish for anyone else?** No
channel-selection rule beats 0.581 and the one that shipped is worst. My answer is
that the mechanism generalises even where the effect size does not, and that the
case-clustered intervals, the permutation null and the held-out split are the parts
worth reusing. The paper says so in one sentence and offers Table 5 as the
generalisable artefact. Judge whether that carries it.

**3.3 Is the container finding already common knowledge?** A previous reviewer pushed
here and was right to: the original claim was not merely obvious, it was wrong. The
replacement is a measured disagreement between two reference validators plus a
reference renderer that ignores the distinction entirely. Push on whether that
disagreement is *interesting* or merely a known defect in one tool that its
maintainers would fix on report. My honest view is that a practitioner cannot act on
the standard alone when the library will not write it, one validator rejects it and
the renderer draws no annotations at all. But it is a judgement call and I would not
be surprised to be told the container half is a bug report rather than a paper.

### Tier 2, could force major revision

**3.4 n = 1 deployed system.** Every claim about "deployed systems" generalises from
one pipeline built by the author. That is a case study. Check that the draft never
reads as a survey.

**3.5 The spline result is entirely synthetic.** 432 studies per condition with known
ground truth bounds what the estimator can do. It says nothing about a clinical rate,
and the draft says so, but a reviewer may want at least one real-data confirmation.

**3.6 The `highdicom` claim is version-pinned and grep-based.** It is true of 0.28.1
and was established by enumerating SOP classes and grepping the installed package for
four attribute names. If the library expresses line style through some other
mechanism, the grep would miss it. Worth an independent check.

**3.7 The paper measures SEG as strictly more conformant than GSPS.** A sharp reviewer
will ask why the reader should not simply use SEG. The paper's answer is that a
presentation state needs no segmentation support in the receiving system; that reason
is cited, not measured here.

### Tier 3, needs a good answer

**3.8** The novelty claim rests partly on a literature absence. Negative claims about
the literature are hard to defend. The search is documented but bounded.

**3.9** I assert that `Laterality` absent is correct for an unpaired body part and
that `dciodvfy` flags it because it cannot evaluate the condition. Check that against
PS3.3 rather than taking it from me.

**3.10** The level assignment is upstream code, 289 of 307 substantive lines verbatim,
and is attributed in the Introduction. Confirm that enough remains that is the
author's own to justify the paper.

**3.11** The AI disclosure is unusually detailed. Judge whether it reads as
transparency or as something that will make a reviewer discount the work regardless.

**3.12** The 558-image internal cohort is described as a developer screening pass and
carries no quantitative claim. Check that it stays that way everywhere.

**3.13** H3, the permission to use the clinical cohort for research, is **closed on
the author's report only**. The thread has not been seen by this ledger. Nothing is
uploaded to satisfy it: IJMI's guide says written consents "must be retained by the
authors" and "should not be provided to this journal unless this is specifically
requested in exceptional circumstances". The same guide reserves the right to request
further evidence, and the author is a former employee whose mailbox access can lapse,
so the artefact could be unavailable if it is ever asked for. That risk is accepted
deliberately, not overlooked; see H5c.

## 4. Where I have already been wrong

Twenty-one retired claims are in the ledger, section G. The ones I stated with most
confidence before being contradicted:

- **That text colour is outside the GSPS IOD while line colour is inside it.** This
  was the paper's headline claim. PS3.3 C.10.5 lists both, and fill style, as Type 3.
  I treated a validator diagnostic as evidence about the standard. Retired as G12.
- **That correcting the channel-selection bug moved the flag from below chance to
  usable.** Computed on 18 of 202 cases. On all 155 scorable cases it is false.
  Retired as G15. The largest correction in the project, caught by finishing the run.
- That a label-informed ceiling of 0.635 showed real headroom. The identical search on
  shuffled labels reaches 0.594 mean over 1000 repetitions. Retired as G16. Note the
  over-correction that followed: I then called it "pure optimism", which D5c-i
  withdraws, because no permutation reached 0.635 so the excess is real. Genuine and
  worthless, not absent.
- **That the reference renderer draws the annotations and discards only their colour.**
  Deleting every annotation, and separately displacing every annotation by 120 px,
  both leave the bitmap byte identical. Retired as G17.
- **That the arm labelled "the deployed rule" was the deployed rule.** It was
  `parity_name`, continuous anatomical parity. The deployed calculator restarts parity
  at C1, T1 and L1 and disagrees with it on 90.2 percent of vertebrae. Added as a
  ninth arm and it is the **worst of the nine** at 0.427. Retired as G20.
- That the checkpoints were locally trained. They are upstream released weights.
- That `torch 2.8.0+cu128` could not run on a Tesla P40. `sm_61` is in the arch list.
- That the VerSe published figures were leaderboard means. They are best single
  algorithms.

The pattern is one thing, four times, and it is worth more than any of the individual
corrections: **the correct answer was already recorded in an artefact this project had
produced, and the paper contradicted it because nobody read the artefact against the
paper.** `results/viewer_bench.md` had G17 a day early.
`tests/test_channels.py::test_the_deployed_confidence_calculator_restarts_parity_at_each_region`
had G20 and its docstring said so outright, and it passed on every run while the paper
carried the contradicting label. The ledger held the clustered intervals that Figure 3
did not draw. Weight anything in the draft accordingly, and check the artefacts against
the prose rather than the prose against itself.
